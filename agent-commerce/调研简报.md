# AI 代理支付协议调研简报:x402 / ACP / TAP

> 调研人:千里眼(alpha-scout)落地执行子任务
> 日期:2026-09-22
> 目的:判断 Hermes agent 集群能否作为「可发现的 agent 服务」接入其中任一协议,靠卖能力收款(收款用 TRON USDT)。
> 约束:只读调研 + 落盘文件,不动真金白银、不注册付费账号。
> 一手来源:x402 白皮书(PDF)、A2A 协议规范 v1.0、A2A x402 扩展规范 v0.1、agenticcommerce.dev、Stripe 官方博客、OpenAI Developers Commerce 文档、Visa Developer / visa/trusted-agent-protocol GitHub、Visa/Mastercard 相关公开报道。

---

## 0. 一句话结论(先给答案)

| 协议 | 定位 | 对「卖 agent 服务」的直接价值 | 个人 agent 可否接入 | 结论 |
|---|---|---|---|---|
| **x402 / A2A-x402** | 链上收付款标准(agent 互相付费) | **高** —— 正是「卖服务收款」的协议 | ✅ 完全开放、无需注册、无需 KYC | **首选,唯一可立刻动手的路径** |
| **ACP(Stripe×OpenAI)** | 电商结账标准(agent 帮人下单) | **低/中** —— 是「卖货/卖服务给消费者」,但要 Stripe 商户 + KYC + 申请 OpenAI 上架 | ⚠️ 需申请、US 优先、禁金融品 | 短期不可行(卡点:申请+商户资质+禁金融品) |
| **TAP(Visa Trusted Agent Protocol)** | 买家侧信任层(agent 替用户刷卡消费) | **无** —— 是「agent 怎么付钱」不是「agent 怎么收钱」 | ❌ 需成为 Visa 注册 trusted agent(发密钥) | 与当前目标无关 |

**核心判断:Hermes 集群想「作为可发现的 agent 服务接入并收款」,能落地的是 x402(尤其 A2A-x402 扩展),但收款必须用 x402 默认的 EVM/USDC 链;用户现有收款是 TRON USDT,这是一个真实的卡点,解法是自建 TRON 验证 facilitator(用户已有 TronGrid 轮询能力,可复用)。ACP/TAP 现阶段都不走通。**

## 1. x402(Coinbase,HTTP 402 支付标准)

### 1.1 是什么
- 由 **Coinbase Developer Platform** 推出,2025-05-06 发布白皮书。复用 HTTP 状态码 **402 "Payment Required"**,让 AI agent / web 服务**按次付费**访问 API、数据、数字服务,去掉 API key、订阅、人工结算。
- 机器原生(M2M)支付:稳定币(主推 **USDC**)在 **Base L2** 结算,约 **200ms** 终局、gas 近零、无 chargeback。
- 完全开源、无需注册账号、无需 KYC、无中间人(permissionless)。

### 1.2 怎么接入(作为「卖服务」的一方)
1. 服务端中间件:`npm install @x402/express-middleware`,`app.get('/premium', x402PaymentRequired({amount, address, assetAddress, network}))`。
2. 没付款时返回 HTTP 402 + 结构化 JSON,字段:`maxAmountRequired` / `assetType`(如 ERC20)/ `assetAddress`(代币合约)/ `paymentAddress`(收款钱包)/ `network`(如 `base-mainnet`)/ `expiresAt` / `nonce` / `paymentId`。
3. agent 用钱包对付款授权做 **EIP-712 签名**,带签名重试请求;服务端验签后广播上链,返回结果。
4. **Facilitator(托管/验证,可选、非托管)**:负责 `POST /verify`(验签)+ `POST /settle`(结算)。Coinbase 官方托管 facilitator 目前支持 **Base、Solana、Polygon、Stellar**;**不含 TRON**。也可自建 facilitator。

### 1.3 需要什么
- 一个可公网访问的 HTTP 服务端点(挂 x402 中间件)。
- 一个收款钱包地址(链上,稳定币)。
- 一个 facilitator:要么用 Coinbase 托管的(仅 Base/Solana/Polygon/Stellar),要么自建(验签 + 查链上到账 + 结算)。

### 1.4 是否开放给个人 agent
**完全开放。** 无需申请、无白名单、无门槛。任何人/任何 agent 都能当「收款方」。(第三方 Bank of AI 甚至宣称其 x402 实现已支持 TRON/BSC/Base,证明 TRON 在协议层面可做,只是不在 Coinbase 官方 facilitator 里。)

### 1.5 A2A-x402 扩展(与本任务最相关)
- Google 系开源组织 **google-agentic-commerce** 出的 **A2A x402 扩展 v0.1**,把 x402 付款接进 **A2A(Agent-to-Agent)协议**,让 agent 直接「卖服务收加密币」。
- 在 **Agent Card**(见第 4 节)里声明扩展:`capabilities.extensions[].uri = https://github.com/google-a2a/a2a-x402/v0.1`,`required: true`。
- 付款流:商家 agent 返回 `input-required` Task + `x402.payment.required`(`accepts[]` 里给 `scheme / network / asset / payTo / maxAmountRequired`);客户 agent 用钱包签名成 `PaymentPayload` 回传;商家验签 → 上链结算 → 返回 `payment-completed` + 收据。
- 默认示例里的 `asset` 是 Base USDC 合约 `0x833589...`,`network:"base"`——**原生是 EVM/USDC,不内置 TRON**。

## 2. ACP(Stripe × OpenAI,Agentic Commerce Protocol)

### 2.1 是什么
- Stripe + OpenAI 联合,2025-09-29 发布,**Apache 2.0** 开源。定义「买家 ↔ AI agent ↔ 商家 ↔ 支付方」之间的**程序化结账**流程,让 ChatGPT 等 agent 帮用户**下单购物**。
- 首场景:**Instant Checkout in ChatGPT**(美国用户买美国 Etsy 商家,随后扩展到百万 Shopify 商家)。
- 商家仍是 **merchant of record**(掌握客户关系、定价、履约);用 **Shared Payment Token**(安全支付令牌)在 agent 与商家之间传支付凭据,PCI 合规。

### 2.2 怎么接入(作为商家/服务方)
1. 实现 ACP 规范,发布 **checkout 配置**(REST 或 MCP 均可)。
2. 给 OpenAI 提交**结构化产品 feed**(file upload 或 API,建议每天全量一次 + 增量)。产品字段:标题/描述/图片/价格/库存等。
3. 对接支付方(Stripe 首个兼容,用 Shared Payment Token;其他 PSP 也可)。
4. **上架 ChatGPT 需单独申请获批**(当前仅限 approved partners)。

### 2.3 需要什么
- **Stripe 商户账号**(或兼容 PSP)→ 涉及公司/主体 KYC、银行账户、合规。用户目前在腾讯云东京 VPS,收款走 TRON USDT,**与 Stripe 法币通道不兼容**。
- 产品 feed + checkout 端点。
- OpenAI 上架审批。

### 2.4 是否开放给个人 agent
**门槛高:**
- 规范本身开源、任何人可读可实现;但「被 ChatGPT 等 agent 实际分销」要**申请 + 平台自选商家**。
- 初始面向 **US**(美国 Etsy/Shopify 商家)。
- 官方**禁售清单明确包含「无牌照金融产品(unlicensed financial products)」**——用户想卖投资情报/回测审计/策略审计这类,大概率踩红线。
- 「商家发现机制(discovery)」官方自述 **仍在开发中**,尚无稳定公开目录。

**结论:ACP 现阶段对「个人 + TRON 收款 + 金融情报类」基本走不通。**

## 3. TAP(Visa Trusted Agent Protocol)& Mastercard Agent Pay

### 3.1 是什么(含一处勘误)
- 背景情报里写的「Visa/Mastercard TAP(Tokenized Agentic Payments)」是**误称**。真实情况:
  - **Visa TAP = Trusted Agent Protocol**(信任代理协议),2025-10-14 发布,Cloudflare 作参考实现。**不是结算协议,是买家侧信任/鉴权层**。
  - Mastercard 对应物叫 **Agent Pay**(基于其 tokenization + Payment Passkey),是另一套。
- TAP 解决的是:**商家如何判断「来下单的 agent 是不是真的、有没有用户授权」**。用 **RFC 9421 HTTP Message Signatures** 对 agent 请求做密码学签名,签名绑定域名+具体操作(browse/pay)+时间戳+会话 ID+密钥 ID,防重放。商家用 Visa 公钥验签。
- 结算仍走**卡网络**,agent 带的是用户**卡上文件的 PAR(Payment Account Reference)**。

### 3.2 怎么接入
- 商家侧:验证 agent 请求签名(Visa 提供公钥目录/撤销 API)。
- **agent 侧:要成为 Visa 注册的 trusted agent**(Visa 运营 launch directory,给 agent 发密钥对,记录 operator id → 公钥)。
- 全链路涉及 Visa 合作伙伴关系、卡网络、发卡行欺诈责任转移(Mastercard Agent Pay:token 有效时发卡行担欺诈责任)。

### 3.3 需要什么 / 是否开放给个人
- 需 **Visa 合作伙伴/注册资格**,个人 agent 无法自助注册上线。
- 与「agent 收加密币卖服务」**方向相反**:TAP 是让 agent **替用户付钱**,不是让 agent **收钱**。

**结论:TAP/Mastercard Agent Pay 与本任务目标(卖服务收款)无关,不纳入落地路径。**

## 4. 「Agent Card」是什么 + 官方 schema(用于第 2 份交付物)

「agent card」在本语境有真实官方格式 = **A2A 协议的 Agent Card(v1.0)**:
- 托管在固定位置 **`https://{域名}/.well-known/agent-card.json`**(IANA 注册的 well-known URI),是 agent 的「数字名片/发现入口」。
- 关键字段(官方 A2A v1.0 规范 §4.4 / §8.5 示例):`name` / `description` / `supportedInterfaces[]`(`url` + `protocolBinding`=JSONRPC|GRPC|HTTP+JSON + `protocolVersion`)/ `provider{organization,url}` / `iconUrl` / `version` / `documentationUrl` / `capabilities{streaming,pushNotifications,extendedAgentCard,extensions[]}` / `securitySchemes` / `securityRequirements` / `defaultInputModes[]` / `defaultOutputModes[]` / `skills[]{id,name,description,tags,examples,inputModes,outputModes}` / `signatures[]`。
- 收款(链上)不在标准 card 里,而是靠 **A2A-x402 扩展**在运行时通过 Task metadata 下发给买家。因此第 2 份 JSON 用「标准 A2A card + 声明 x402 扩展 + 一个自拟的 `x402-payment` 字段」承载 TRON 收款信息(说明见交付物内注记)。

## 5. Hermes agent 集群:能否落地接入?(最终判断)

### 5.1 能落地:是(x402 / A2A-x402 路径),但要分两步
**第一步(纯协议、零新依赖):** 发布一张只读 **A2A Agent Card**(`/.well-known/agent-card.json`)+ 声明 x402 扩展,让集群成为「可发现的 agent 服务」。
**第二步(收款闭环):** 用已有 `tron-usdt-payment` 的 TronGrid 轮询能力,自建一个 **TRON 版 x402 facilitator / 自定义 scheme**,在 A2A 消息里声明 `network:"tron"`、`asset:"TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t"`(USDT-TRC20 合约)、`payTo:"TLnnmqLiY4CE8bnekow6ikpjDHoytJP5p3"`。这样买家用 TRON USDT 付款,监听器按「唯一金额尾数匹配」锁单(机制现成)。

### 5.2 卡点(按严重度)
1. **TRON ≠ x402 默认链**:x402 官方 facilitator 只支持 Base/Solana/Polygon/Stellar;TRON 需自建 facilitator/自定义 scheme。工作量中等,但用户已有 TronGrid 收款监听,可复用,不是从零。
2. **公网端点/域名缺失**:A2A 发现依赖 `https://域名/.well-known/agent-card.json`;当前集群在东京 VPS、有公网 IP 但**未配公网域名/HTTPS 终止**。需先有域名 + Cloudflare/Nginx 终结 TLS(参考 `systemd-user-service-ops` / `tron-usdt-payment` 的加固清单)。
3. **发现目录碎片化**:A2A 没有唯一官方市场;有 a2a-registry.org、a2a-directory 等第三方目录,靠手动登记,能见度有限——「可发现」不等于「有流量」。
4. **ACP/TAP 基本排除**(见第 2、3 节):ACP 需 Stripe 商户 + OpenAI 申请 + 禁金融品;TAP 是买家侧且需 Visa 注册。

### 5.3 明确结论
- **能落地接入,路径唯一且明确:走 A2A + A2A-x402 扩展,收款保留 TRON USDT(自建 TRON facilitator)。**
- **下一步第一步动作:** ① 确定一个公网域名并终结 TLS(先决条件);② 把交付的 `agent-card.json` 挂到 `/.well-known/agent-card.json`;③ 接一个最小 A2A 服务(如 `a2a-python`)暴露一个可调用 skill(先拿「每日情报简报」当第一个付费能力);④ 把 TronGrid 轮询包成 x402 自定义 scheme 的 verify/settle。
- **暂不碰** ACP(申请+资质+禁金融品)与 TAP(买家侧,需 Visa 注册)。
